HTTP, API och Network

När webbläsaren behöver något från en server skickar den en request och får en response tillbaka. Det gäller när en sida laddas och när ett formulär skickas. Network-fliken i DevTools visar varje sådan förfrågan.

Det här kan du efteråt

  • Skilja på GET och POST.
  • Läsa status, headers och body i Network-fliken.
  • Förklara vad ett API och en endpoint är.

Begrepp

GET
Hämtar något, till exempel en sida eller en låtlista.
POST
Skickar data som ska tas emot eller sparas, till exempel ett formulär.
API
Serverns "dörrar": adresser man kan skicka requests till.
Endpoint (endpoint)
En enskild adress i ett API, till exempel /api/spelhistorik.
Statuskod (status code)
Serverns korta besked, till exempel 200 (gick bra) eller 404 (finns inte).
Header (header)
Extra uppgifter som följer med en request eller response, till exempel Content-Type.

Delarna i en request och en response

  • Request

    Metod (GET eller POST), adress, headers och ibland en body med data.

  • Response

    Statuskod, headers och en body med innehållet, till exempel HTML eller JSON.

Statuskoderna går i grupper: 2xx gick bra, 3xx omdirigering, 4xx klienten gjorde fel (404 saknas), 5xx servern gjorde fel.

Skicka requests från JavaScript

Prova i webbläsaren

  1. Öppna DevTools och fliken Network. Slå på Disable cache och ladda om sidan.
  2. Filtrera på Fetch/XHR för att se anrop som sidans JavaScript gör.
  3. Klicka på en rad. Läs flikarna Headers, Payload och Response.
  4. Vilken metod och vilken statuskod har förfrågan? Vad skulle ändras om du skrev fel adress?
